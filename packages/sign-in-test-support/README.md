# Sign-in test support

Owns controlled inputs, native CLI drivers and real storage hosts for the [sign-in packages](../sign-in-core). It is private test infrastructure.

The shared storage cases execute inside real workerd with D1, or under Node with a real `better-sqlite3` file. Wrangler applies D1 migrations before the Worker starts; Drizzle's SQLite migrator initializes the file leg. Both consume [the same checked-in migration](../sign-in-core/drizzle). The SQLite leg proves storage and provider integration; it does not supply a production Node HTTP host.

From the monorepo root:

```sh
mise exec node@24.7.0 -- pnpm build
mise exec node@24.7.0 -- pnpm exec vitest run --project e2e-host packages/sign-in-test-support
mise exec node@24.7.0 -- node packages/sign-in-test-support/node_modules/drizzle-kit/bin.cjs generate --config packages/sign-in-test-support/drizzle.config.mts
```

The [verify-auth skill](../../.agents/skills/verify-auth/SKILL.md) owns target-bound `bootstrap`, `agent` and `people` journeys. It records source, host, prepared artifacts, actual runtime module hashes and private receipts. Production auth and Gateway modules are built from package artifacts without test transformations; separate test modules provide controlled Date and invocation-scoped native-signing observation. Signing observation forwards the native operation unchanged and retains only the client/organization/workspace projection after completion. Negative `__proof` provider routes are separate controls.

Turnstile cases send social starts and passkey sign-in challenges through the selected native host. Passkey sign-in is click-only: native `GET /api/auth/passkey/generate-authenticate-options` requires a fresh Turnstile token, and native `POST /api/auth/passkey/verify-authentication` requires user verification. The [passkey sign-in host cases](src/people-passkey-sign-in.host.e2e.test.ts) run on both Node and workerd; the [real-Chrome V8 journey](src/sign-in-native-browser.host.e2e.test.ts) drives the delivered button and native CLI with Chrome's virtual authenticator. Separately labelled provider-level cases send real Requests through Better Auth's handler to prove captcha precedes sign-in challenge writes. A single-use token registry is the external siteverify stand-in, using published test keys. It records only requests matching that dummy secret. Provider responses and clocks are controlled. Physical authenticators, real provider identity, real siteverify, real-token replay and staging remain private-stack proof.

The passkey page case executes the delivered HTML controls and JavaScript in a DOM, with a controlled `navigator.credentials` backed by the software EC authenticator. It sends the controller's serialized binary responses through real HTTP to the selected host's native verifier and storage. It proves that transport, without claiming a real browser, physical authenticator or biometric check.

Request-limit cases give each fixture browser a stable address through the existing trusted-proxy or edge boundary. Node's host counter and Better Auth's memory counter use the controlled clock. On Cloudflare the exact service-page budget case replaces only that counter through the test binding seam, using the injected clock: the first 429 is request 301, stored state is unchanged and a second address passes. Its receipt names `cloudflare-controlled-binding-stand-in` and `proofCase: service-page-exact-budget`; it earns no real-limiter or vendor credit. Miniflare's real limiter uses wall-clock-aligned windows, so a separate default-workerd wiring case requires a real 429 by request 601 (at most one rollover), unchanged state and a second address passing. Neither case reads or waits on real time. Other Cloudflare limit cases retain the real binding. The window reset is proven where it runs on the controlled clock: Better Auth's provider-layer limit (the recovery-code case moves the harness clock) and the Node host's fixed-window counter. The hosted binding's reset and cross-location counting are checked on the private stack.

Each harness receipt names its outer counter and retains the actual request-limit observations with their `outer` or `provider` layer. The journey driver requires the host's real counter (`node-fixed-window` or `cloudflare-real-binding`) except for exactly one named exact-budget stand-in in `people` on workerd. Missing, duplicate, unnamed or unrelated stand-ins fail admission; every other journey and all Node receipts stay strict on real counters. Its summary reports the counter mix and `cloudflareVendorCredit: false`.

One additional people case per host explicitly arms a backing failure after normal readiness: the Node counter port throws, or a stand-in at the Cloudflare binding boundary rejects its promise. The receipt records `backingFailure`, and the summary counts each kind separately. The request must return 503 with no additional native captcha or stored state effects. Changing a spoofed `x-forwarded-for` is tested below the real Cloudflare outer budget, so it establishes trusted-address keying without vendor throttle credit.

The served owner-page cases drive the actual social, app setup/confirmation, organization creation or selection, and Continue forms back to the original native CLI loopback. Their driver never navigates an authorization URL saved from the launch. It learns app setup material from the one-time HTML and consumes native cookie changes through the browser jar.

Miniflare's structured-log callback retains the actual Cloudflare JSON observations. A test-wrapper UUID marker drains that stream by event, without polling or a sleep. Private provider envelopes also retain per-invocation observations for overlap assertions. Native-hook comparison checks response transparency separately from provider-handler and public-Worker proof. Failed connections are real loopback connection refusals; a verifier hanging until the library's timeout stays unverified locally.

Write faults target a table, operation and bound identity at the recording driver. Atomic-group membership tests are separate from the real second-statement key-conflict rollback proof. Shared barriers live in Node so every Worker invocation owns its outbound wait. Tests advance controlled clocks or await explicit events.
